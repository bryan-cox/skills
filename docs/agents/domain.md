# Domain docs

This is a single-context repo with repo-specific glossary and ADR paths. Use these paths rather than creating `CONTEXT.md` or `docs/adr/` as setup scaffolding.

## Before exploring

- Read `GLOSSARY.md` for the project's vocabulary.
- Read relevant decisions in `.agents/adr/` before changing or proposing work in those areas.
- Use glossary terms in issues, specs, and other outputs. If a term is missing, note the gap rather than inventing a synonym.
- If a proposal or change conflicts with an ADR, surface the conflict explicitly.

## Layout

- `GLOSSARY.md`: canonical project vocabulary.
- `.agents/adr/`: architecture decision records.
